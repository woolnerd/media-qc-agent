04 · Safety rules

A callback is evidence, not automatic authority

Each event is classified using its job ID and the run's current state. Only the active submitted job may create and promote a video.

CompletionDispositionEffect
Active submitted jobappliedCreate one video; mark run succeeded.
Same event ID againreuse originalNo new write or transition.
Another completion for succeeded jobredundantAudit event; keep existing video.
Superseded jobstaleAudit event; do not promote video.
Active job in impossible staterejectedAudit reason; do not advance run.

05 · Talk track

Tell one failure-to-repair story

“A visual-quality finding should retry the expensive video without throwing away approved upstream work. The policy proposes that boundary, a human approves it, and the callback can promote a version only for the active job.”

Why SQLite and a fake?

They let the project prove transactional event handling, idempotency, and crash recovery before adding a real provider or worker.

Why immutable versions?

A retry changes the active pointer while prior videos, captions, and exact input lineage remain inspectable.

Why separate event disposition?

A late callback remains visible for audit without changing run status or replacing the active output.

# Agentic workflow value against a rules-only baseline

Issue #28 asks where model-assisted interpretation improves outcomes over
deterministic checks plus human review, not just whether a model predicts the
right label. This page is the protocol. The held-out cases, ground truth,
metrics, weights, and decision rule were committed before any model ran on
these cases; git history records the order.

## Arms

All arms receive the same synthetic artifacts, run the same deterministic gates
(environment, spoken text, captions, motion), use the same minimum-repair
policy (`plan_repair`), and require the same human approval. They differ only
in who routes free-text review feedback:

| Arm | Gate finding present | Gates silent |
| --- | --- | --- |
| `rules_only` | Gate finding gets a repair plan | A human diagnoses the feedback |
| `single_shot` | The model decides (gate evidence is in its input) | The model decides |
| `layered` (current design) | Gate finding gets a repair plan; the model is not consulted | The model decides |

A model decision with repair authority must pass validation and the
`grounded-scope-v2` acceptance policy. An abstention, rejected output, or
provider error goes to a human for diagnosis, as in `rules_only`.

### Which behaviors exist

Issue #28 distinguishes a single-shot classifier from an agent that chooses
evidence, asks for clarification, and reassesses a replacement. In this
codebase:

- **Feedback routing** is the only model behavior: one structured turn per case.
- **Evidence selection is not implemented.** Every arm receives the same
  precomputed gate and reviewer evidence. No result here can be credited to it.
- **Clarification** is deterministic: environment mismatches always ask the
  human to choose a branch, and an abstention asks for a diagnosis.
- **Replacement reassessment** is deterministic: the same gate re-runs on the
  replacement, or a human re-reviews it when no gate covers the defect.

The comparison attributes differences to these behaviors: `layered` versus
`rules_only` isolates model routing on gate-silent cases; `single_shot` versus
`layered` isolates gate precedence. Clarification and reassessment counts are
reported per arm; they cannot differ unless routing differs.

## Held-out cases

[`evals/baseline-cases-v1.json`](../../evals/baseline-cases-v1.json) holds 19
new synthetic cases, none used for prompt development. Each of the five failure
classes has clear, ambiguous, and adversarial cases. Some clear cases are
**gate gaps**: a real defect no deterministic gate detects, such as an
abbreviation read aloud wrongly, a caption typo, lip-sync drift, or a
script/environment conflict the scene metadata cannot express. A reviewer
attaches a fact for these. Version IDs (`script-h01`) carry no class hints.

Each case has structured artifacts the gates actually run on (script text and
scene, avatar environment, provider-facing text and TTS profile, caption cues,
motion samples), reviewer feedback, reviewer-attached evidence, and ground
truth:

| Field | Meaning |
| --- | --- |
| `defect` | Diagnosis the supplied evidence supports, or null when it supports none |
| `evidence_artifacts` | Artifacts whose facts support the diagnosis |
| `earliest_gate` | `pre_render` or `post_render` |
| `acceptable_repairs` | Each acceptable action and its exact invalidations |
| `preserve` | Artifacts no acceptable repair replaces |
| `human_decision` | `approve_repair`, `choose_branch`, or `diagnose` |
| `post_repair_check` | `gate` when a gate can verify the replacement, else `human_review` |
| `post_repair_outcome` | What an acceptable result looks like |

Tests check that gate annotations match gate behavior and that acceptable
repairs match the minimum-repair policy.

## Metrics

Per case and arm, from `cli/baseline_metrics.py`:

- **Safety (never averaged):** false passes (repair authority for a wrong or
  unsupported diagnosis), wrong repairs (an authorized action or scope that is
  not acceptable), unauthorized actions (repair authority where a human branch
  choice was required), extra provider jobs (video regenerated by a wrong plan).
- **Other errors:** false blocks (a supported defect held for human diagnosis)
  and rejected model outputs.
- **Waste:** unnecessary invalidations (preserved artifacts an authorized plan
  would replace) and extra provider jobs.
- **Human effort (modeled):** diagnosis, clarification, approval, correction,
  and post-repair re-review rounds.
- **Time and cost:** recorded model seconds and USD, modeled human minutes,
  synthetic provider cost, and their sum.
- **Evidence and uncertainty:** authorized decisions citing no fact or a fact
  outside the ground-truth artifacts; model holds on ambiguous cases that do
  not cite the supplied uncertainty.
- **Late detection:** pre-render defects that only post-render review found.

Results are reported per run, summed, by failure class and by category, and
as paired per-case changes against `rules_only` with every worse case listed.

### Modeling assumptions (pre-registered)

| Round | Minutes |
| --- | --- |
| Diagnosis (human reads feedback and artifacts, names the defect) | 10 |
| Clarification (human chooses a creative branch) | 3 |
| Approval review of a repair plan | 2 |
| Correction after a wrong plan executed | 15 |
| Post-repair re-review when no gate verifies the replacement | 5 |

- Human time is valued at $60/hour. A video regeneration costs a synthetic $2;
  local caption repair costs nothing.
- The human diagnoses correctly. This favors `rules_only`.
- A wrong authorized plan executes before anyone notices, then costs a
  correction round. This is the worst case for the model arms.
- Every arm needs the same final approval, branch choice, and re-review for
  the correct repair; they differ in diagnosis, wasted clarification,
  correction, and extra approvals.

Round counts are reported separately so readers can apply other weights.

## Decision rule (pre-registered)

An arm is compared with `rules_only` across all recorded runs:

1. **Reject** if, summed across runs, it exceeds `rules_only` on any safety
   metric. Saved minutes cannot offset a safety regression.
2. Otherwise **adopt** only if it reduces modeled human minutes by at least
   15% in every run.
3. Otherwise report **no demonstrated value**.

`rules_only` has no model, so any model false pass rejects an arm. That is
deliberate: the model is meant to save human time without new safety risk.

## Limits

- Nineteen synthetic cases demonstrate the architecture and catch regressions.
  They do not estimate real-world productivity, accuracy, or calibration.
- Human effort is a model with stated weights, not a measurement. The case
  author also wrote the ground truth.
- Gate-gap facts were written by a synthetic reviewer, who has already done
  part of the diagnosis. The 10-minute diagnosis weight may overstate what
  routing saves.
- Validating productivity claims would need blinded human review of real or
  permitted workflow data: reviewers timed on matched cases with and without
  model routing, ground truth from independent annotators, and observed rates
  at which approvers catch wrong plans in place of the worst-case assumption.
